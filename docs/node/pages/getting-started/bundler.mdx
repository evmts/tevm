# Tutorial: Importing `.sol` Files Directly

Normally, wiring a Solidity contract into TypeScript means running `forge build` or `hardhat compile`, copying ABI JSON files, running a codegen CLI, and hoping your generated types stay in sync when a `.sol` file changes.

The Tevm Bundler turns `.sol` files into ordinary ES modules at build time — with a TypeScript language service plugin (`@tevm/ts-plugin`) giving you live type errors and NatSpec on hover before you even save.

<BundlerPipelineDiagram />

## 1. Install

```bash
pnpm add tevm viem
```

All bundler plugins ship inside `tevm/bundler/*`:

| Bundler | Entry point | Export |
| --- | --- | --- |
| Vite | `tevm/bundler/vite-plugin` | `vitePluginTevm()` |
| Rollup | `tevm/bundler/rollup-plugin` | `rollupPluginTevm()` |
| esbuild | `tevm/bundler/esbuild-plugin` | `esbuildPluginTevm()` |
| Webpack | `tevm/bundler/webpack-plugin` | `new WebpackPluginTevm()` |
| Rspack | `tevm/bundler/rspack-plugin` | `rspackPluginTevm()` |
| Bun | `tevm/bundler/bun-plugin` | `bunPluginTevm()` |

## 2. Register your bundler plugin

:::code-group

```ts [Vite]
// vite.config.ts
import { defineConfig } from 'vite'
import { vitePluginTevm } from 'tevm/bundler/vite-plugin'

export default defineConfig({
  plugins: [vitePluginTevm()],
})
```

```ts [esbuild]
import { build } from 'esbuild'
import { esbuildPluginTevm } from 'tevm/bundler/esbuild-plugin'

await build({
  entryPoints: ['src/index.ts'],
  bundle: true,
  outfile: 'dist/index.js',
  plugins: [esbuildPluginTevm()],
})
```

```ts [Rollup]
// rollup.config.ts
import { rollupPluginTevm } from 'tevm/bundler/rollup-plugin'

export default {
  input: 'src/index.ts',
  output: { dir: 'dist', format: 'esm' },
  plugins: [rollupPluginTevm()],
}
```

```ts [Webpack]
// webpack.config.ts
import { WebpackPluginTevm } from 'tevm/bundler/webpack-plugin'

export default {
  plugins: [new WebpackPluginTevm()],
}
```

```ts [Rspack]
// rspack.config.ts
import { rspackPluginTevm } from 'tevm/bundler/rspack-plugin'

export default {
  plugins: [rspackPluginTevm()],
}
```

```ts [Bun]
// plugins.ts (referenced from preload = ["./plugins.ts"] in bunfig.toml)
import { plugin } from 'bun'
import { bunPluginTevm } from 'tevm/bundler/bun-plugin'

plugin(bunPluginTevm({}))
```

:::

<WatchOut title="Webpack uses a class constructor">
Every bundler plugin is a lowercase factory function (`vitePluginTevm()`, `esbuildPluginTevm()`, etc.) **except** Webpack, which exports the class `WebpackPluginTevm` and must be instantiated with `new WebpackPluginTevm()`.
</WatchOut>

## 3. Enable TypeScript IDE support

Add `@tevm/ts-plugin` to your `tsconfig.json` so your editor resolves `.sol` imports, shows NatSpec documentation on hover, and flags mismatched arguments immediately:

```json
{
  "compilerOptions": {
    "plugins": [{ "name": "@tevm/ts-plugin" }]
  }
}
```

## 4. Import a contract and run it

Write a Solidity contract anywhere in your project (imports from `node_modules` and Foundry `remappings.txt` / `foundry.toml` work out of the box):

```solidity
// src/Counter.sol
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

contract Counter {
    uint256 public number;

    function setNumber(uint256 next) public {
        number = next;
    }
}
```

Import `Counter` directly and use its typed `deploy`, `read`, and `write` action creators with Tevm or viem:

```ts
import { Counter } from './Counter.sol'
import { createMemoryClient, PREFUNDED_ACCOUNTS } from 'tevm'

const client = createMemoryClient({
  account: PREFUNDED_ACCOUNTS[0],
})

try {
  const hash = await client.deployContract(Counter.deploy())
  const receipt = await client.getTransactionReceipt({ hash })
  const counter = Counter.withAddress(receipt.contractAddress!)

  await client.writeContract(counter.write.setNumber(42n))
  const value = await client.readContract(counter.read.number())

  console.log(value) // 42n
} finally {
  await client.tevmClose()
}
```

<UnderTheHood>
Each compiled `.sol` module exports one `Contract` object per contract declared in the file. That object carries `abi`, `humanReadableAbi`, `bytecode`, `deployedBytecode`, `withAddress(addr)`, `deploy(...)`, `read.*`, `write.*`, and `events.*` — all typed via `abitype` so viem and Tevm infer parameter and return types end-to-end.
</UnderTheHood>

<QaBox question="Can I use the Tevm Bundler in a browser frontend even though the native engine runs in Node.js?">
Yes. The bundler compiles Solidity at **build time** and emits pure JavaScript/TypeScript contract objects (`abi`, `read`, `write`, `events`) with zero native dependencies. Use those compiled imports in any React, Svelte, or Next.js frontend with standard viem or wagmi, and connect to `@tevm/server` over HTTP/WebSocket during local development.
</QaBox>
