# Tutorial: Driving Tevm with Ethers v6

You have an existing ethers v6 application or test suite and want to run it against an in-process native EVM without spinning up an external RPC server.

Tevm supports ethers v6 in two ways:

<CompareGrid>
  <CompareCard title="TevmProvider (@tevm/ethers)" badge="Recommended">
    Subclasses ethers' <code>JsonRpcApiProvider</code>, disables ethers' read cache automatically, wires directly to native <code>rpc()</code>, and exposes <code>provider.tevm</code> for cheatcodes and mining.
  </CompareCard>
  <CompareCard title="BrowserProvider(client)" badge="Zero extra packages">
    Wraps <code>createMemoryClient()</code> via EIP-1193. Pass <code>{'{ cacheTimeout: -1 }'}</code> so ethers never returns stale state after local mutations.
  </CompareCard>
</CompareGrid>

## 1. Install

:::code-group

```bash [pnpm]
pnpm add tevm viem ethers@6 @tevm/ethers
```

```bash [npm]
npm install tevm viem ethers@6 @tevm/ethers
```

:::

*(Omit `@tevm/ethers` if you prefer wrapping `createMemoryClient()` in ethers' built-in `BrowserProvider`.)*

## 2. Create a provider and fund a wallet

```ts
import { TevmProvider } from '@tevm/ethers'
import { Wallet, formatEther, parseEther } from 'ethers'
import { getAddress } from 'tevm'

const provider = await TevmProvider.createMemoryProvider({
  mining: { auto: false },
})

try {
  const signer = Wallet.createRandom().connect(provider)

  // Use provider.tevm (a full MemoryClient) for local state setup
  await provider.tevm.setBalance({
    address: getAddress(signer.address),
    value: parseEther('10'),
  })

  const balance = await provider.getBalance(signer.address)
  console.log('Funded balance:', formatEther(balance), 'ETH') // 10.0 ETH

  // Send a transaction through ethers
  const tx = await signer.sendTransaction({
    to: '0x1111111111111111111111111111111111111111',
    value: parseEther('1'),
  })

  // Manual mining is enabled, so mine before waiting for the receipt
  await provider.tevm.mine({ blocks: 1 })
  const receipt = await tx.wait()

  console.log('Receipt status:', receipt?.status) // 1
} finally {
  // Stops ethers polling and closes the native ZEVM engine
  provider.destroy()
}
```

<QaBox question="Why does TevmProvider have a .tevm property?">
Ethers' `Provider` interface only covers standard Ethereum JSON-RPC reads and transaction submission. Exposing the underlying `MemoryClient` on `provider.tevm` lets you call `setBalance`, `setCode`, `snapshot`, `revert`, `mine`, and `tevmCall` without juggling two disconnected objects.
</QaBox>

## Alternative: Using ethers' `BrowserProvider`

If you do not want to install `@tevm/ethers`, pass a `MemoryClient` directly to `BrowserProvider`:

```ts
import { BrowserProvider, Wallet, parseEther } from 'ethers'
import { createMemoryClient, getAddress } from 'tevm'

const client = createMemoryClient()

try {
  await client.tevmReady()

  const provider = new BrowserProvider(client, undefined, {
    cacheTimeout: -1,
  })
  const signer = Wallet.createRandom().connect(provider)

  await client.setBalance({
    address: getAddress(signer.address),
    value: parseEther('10'),
  })

  // Automining is on by default, so tx.wait() resolves immediately
  const tx = await signer.sendTransaction({
    to: '0x1111111111111111111111111111111111111111',
    value: parseEther('1'),
  })
  const receipt = await tx.wait()
  console.log('Mined in block:', receipt?.blockNumber)
} finally {
  await client.tevmClose()
}
```

<WatchOut title="Do not forget cacheTimeout: -1 with BrowserProvider">
By default, ethers v6 caches `eth_blockNumber` and account reads briefly. In tests where you mutate balances or mine blocks back-to-back, leaving the default cache enabled causes ethers to return the previous block's values. `TevmProvider` sets `cacheTimeout: -1` for you automatically.
</WatchOut>
