# Tutorial: Driving Tevm with Viem

If you already know [viem](https://viem.sh), you already know most of Tevm. `createMemoryClient()` is a standard viem client whose transport routes directly into an in-process native ZEVM engine.

## Choose your client shape

<CompareGrid>
  <CompareCard title="createMemoryClient()" badge="Recommended">
    Attaches all viem <strong>public</strong>, <strong>wallet</strong>, <strong>test (Anvil)</strong>, and <strong>TEVM</strong> actions in one call. Best for tests, scripts, backends, and CLIs.
  </CompareCard>
  <CompareCard title="createClient + createTevmTransport()" badge="Tree-shakeable">
    Builds a minimal viem client with only the standalone actions you import from <code>viem/actions</code> and <code>tevm</code>. Best when keeping dependency footprint tight.
  </CompareCard>
</CompareGrid>

## Walkthrough: One client, four action surfaces

Every action surface talks to the exact same native state. You can fund an account with a test action, send a transaction with a wallet action, mine with a TEVM action, and read the receipt with a public action.

```ts
import { createMemoryClient, parseEther, PREFUNDED_ACCOUNTS } from 'tevm'

const client = createMemoryClient({
  account: PREFUNDED_ACCOUNTS[0],
  mining: { auto: false },
})

try {
  const bob = '0x1111111111111111111111111111111111111111'

  // 1. viem test action (Anvil-compatible)
  await client.setBalance({
    address: PREFUNDED_ACCOUNTS[0].address,
    value: parseEther('50'),
  })

  // 2. viem wallet action
  const hash = await client.sendTransaction({
    to: bob,
    value: parseEther('1'),
  })

  // 3. viem test action or TEVM action — both accept { blocks }
  await client.mine({ blocks: 1 })

  // 4. viem public action
  const receipt = await client.getTransactionReceipt({ hash })

  // 5. TEVM account helper (returns bigint balance/nonce + code + storage)
  const account = await client.tevmGetAccount({ address: bob })

  console.log(receipt.status, account.balance) // 'success' 1000000000000000000n
} finally {
  await client.tevmClose()
}
```

<QaBox question="When should I use readContract vs. tevmContract?">
Use viem's `readContract` / `writeContract` when you want portable code that works identically against an RPC provider in production.

Reach for `tevmContract` (or `tevmCall`) when you want a single call that supports `stateOverride`, `addToMempool`, or `addToBlockchain` without assembling separate transactions.
</QaBox>

## Deploy and interact with a contract

Tevm bundles sample contracts in `tevm/contract` (`SimpleContract`, `ERC20`, `ERC721`, `ErrorContract`) for quick experiments, or you can pass any ABI and bytecode from Foundry, Hardhat, or the [Tevm Bundler](./bundler).

```ts
import { createMemoryClient, PREFUNDED_ACCOUNTS } from 'tevm'
import { SimpleContract } from 'tevm/contract'

const client = createMemoryClient({
  account: PREFUNDED_ACCOUNTS[0],
})

try {
  // Deploy with constructor arg 7n (automines by default)
  const hash = await client.deployContract(SimpleContract.deploy(7n))
  const receipt = await client.getTransactionReceipt({ hash })
  const contract = SimpleContract.withAddress(receipt.contractAddress!)

  // Read with viem
  console.log('Initial:', await client.readContract(contract.read.get())) // 7n

  // Write with viem
  await client.writeContract(contract.write.set(42n))
  console.log('Updated:', await client.readContract(contract.read.get())) // 42n
} finally {
  await client.tevmClose()
}
```

## Tree-shakeable setup with `createTevmTransport`

If you want only specific actions, compose a plain viem `createClient` with `createTevmTransport()` and call standalone functions from `viem/actions` and `tevm`:

```ts
import { createTevmTransport, tevmCall, tevmDumpState } from 'tevm'
import { createClient } from 'viem'
import { getBlockNumber } from 'viem/actions'

const transport = createTevmTransport()
const client = createClient({ transport })

try {
  const blockNumber = await getBlockNumber(client)

  // Standalone actions accept any RpcClient (client or client.transport.tevm)
  const call = await tevmCall(client, {
    to: '0x0000000000000000000000000000000000000123',
    stateOverride: {
      '0x0000000000000000000000000000000000000123': {
        code: '0x602a60005260206000f3',
      },
    },
  })

  const stateBlob = await tevmDumpState(client)
  console.log(blockNumber, call.rawData, stateBlob.slice(0, 18))
} finally {
  await client.transport.tevm.close()
}
```

<UnderTheHood>
`createMemoryClient` sets `cacheTime: 0` on the underlying viem client so viem never serves stale block numbers or balances after a local `setBalance`, `revert`, or `mine`. If you build a custom `createClient({ transport: createTevmTransport() })`, pass `cacheTime: 0` there too.
</UnderTheHood>

## Raw EIP-1193 requests

Every `MemoryClient` exposes viem's `request({ method, params })` directly to ZEVM:

```ts
import { createMemoryClient } from 'tevm'

const client = createMemoryClient()

try {
  const chainId = await client.request({ method: 'eth_chainId' })
  const blockNumber = await client.request({ method: 'eth_blockNumber' })
  console.log(chainId, blockNumber) // '0x7a69' '0x0'
} finally {
  await client.tevmClose()
}
```

<WatchOut title="No JSON-RPC envelope in client.request()">
Pass `{ method, params }` — never `{ jsonrpc: '2.0', id: 1, method }`. If you need raw JSON-RPC wire strings (including batches or notifications), call `client.transport.tevm.rpc(jsonString)`.
</WatchOut>
