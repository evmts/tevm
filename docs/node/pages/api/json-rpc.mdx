# JSON-RPC reference

Every call in Tevm — whether through `createMemoryClient()`, `createZevmEngine()`, `TevmProvider`, or `@tevm/server` — is dispatched by ZEVM's native JSON-RPC router.

## Enabled RPC modules

Query `rpc_modules` on any engine to inspect active namespaces:

```json
{
  "eth": "1.0",
  "net": "1.0",
  "web3": "1.0",
  "rpc": "1.0",
  "txpool": "1.0",
  "debug": "1.0",
  "engine": "1.0",
  "zevm": "1.0"
}
```

Development cheatcode methods are also available under `anvil_*` and `evm_*`.

## Dispatching requests

Two host methods exist, with distinct contracts:

| Method | Input | Output | Use when |
| --- | --- | --- | --- |
| `client.request({ method, params })` / `engine.request(...)` | EIP-1193 object (no `jsonrpc`/`id`) | Parsed `result`; throws `NativeRpcError` on error | Application code, viem, scripts |
| `engine.rpc(jsonString)` | Raw JSON-RPC 2.0 string (single, batch, or notification) | Exact JSON response string, or `null` for notifications | HTTP/WS/IPC servers, wire conformance tests |

```ts
import { createZevmEngine } from 'tevm/node'

const engine = createZevmEngine()
try {
  // EIP-1193 shape
  const chainId = await engine.request({ method: 'eth_chainId' })

  // Raw JSON-RPC batch
  const batch = await engine.rpc(
    JSON.stringify([
      { jsonrpc: '2.0', id: 1, method: 'eth_blockNumber' },
      { jsonrpc: '2.0', id: 2, method: 'web3_clientVersion' },
    ]),
  )

  console.log(chainId, JSON.parse(batch!))
} finally {
  await engine.close()
}
```

## Core method groups

### Standard Ethereum (`eth_*`, `net_*`, `web3_*`, `rpc_*`)

- **Chain & accounts:** `eth_chainId`, `eth_accounts`, `eth_blockNumber`, `eth_gasPrice`, `eth_maxPriorityFeePerGas`, `eth_feeHistory`, `eth_blobBaseFee`, `net_version`, `web3_clientVersion`, `rpc_modules`
- **State reads:** `eth_getBalance`, `eth_getCode`, `eth_getStorageAt`, `eth_getTransactionCount`, `eth_getProof`
- **Execution & estimation:** `eth_call` (with `stateOverride`), `eth_estimateGas`, `eth_createAccessList`
- **Transactions & receipts:** `eth_sendTransaction`, `eth_sendRawTransaction`, `eth_signTransaction`, `eth_getTransactionByHash`, `eth_getTransactionReceipt`, `eth_getBlockReceipts`
- **Blocks & logs:** `eth_getBlockByNumber`, `eth_getBlockByHash`, `eth_getLogs`, `eth_newFilter`, `eth_newBlockFilter`, `eth_newPendingTransactionFilter`, `eth_getFilterChanges`, `eth_getFilterLogs`, `eth_uninstallFilter`
- **Subscriptions (over `@tevm/server` WS/IPC):** `eth_subscribe` (`newHeads`, `logs`, `newPendingTransactions`, `syncing`), `eth_unsubscribe`

### Development controls (`anvil_*`, `evm_*`, `zevm_*`)

- **Accounts & storage:** `zevm_getAccount`, `anvil_setBalance`, `anvil_setNonce`, `anvil_setCode`, `anvil_setStorageAt`, `anvil_impersonateAccount`, `anvil_stopImpersonatingAccount`, `anvil_autoImpersonateAccount`
- **Mining & time:** `anvil_mine`, `evm_mine`, `anvil_getAutomine`, `evm_setAutomine`, `evm_setIntervalMining`, `evm_setNextBlockTimestamp`, `evm_increaseTime`
- **Snapshots & state blobs:** `evm_snapshot`, `evm_revert`, `anvil_dumpState`, `anvil_loadState`, `anvil_reset`

### Tracing & mempool (`debug_*`, `txpool_*`)

- **`debug_traceCall`** — native Guillotine Mini opcode tracer supporting `{ disableStack, enableMemory, enableReturnData, disableStorage: true }`. Retains up to 100,000 steps and reports `truncated`.
- **`txpool_status`**, **`txpool_content`**, **`txpool_contentFrom`**, **`txpool_inspect`** — pending and queued transaction inspection.

## Wire encoding rules

Native JSON-RPC enforces strict Ethereum JSON-RPC wire encoding:

- **Quantities** (block numbers, balances, nonces, gas, chain ID) are lowercase unpadded hex strings with a `0x` prefix (`'0x0'`, `'0x7a69'`, `'0x2a'`). Never pass decimal strings or `BigInt` values directly into `engine.request()`.
- **Data** (addresses, hashes, bytecode, storage values) are `0x`-prefixed hex strings.
- **Missing lookups** (such as `eth_getTransactionByHash` or `eth_getTransactionReceipt` for an unknown or unmined hash) return `null`.

Host helpers (`createMemoryClient`, `tevmGetAccount`, `tevmSetAccount`, `tevmCall`, `tevmMine`, `tevmDeal`) handle `bigint` ↔ hex quantity conversion for you automatically.

## Error codes (`NativeRpcError`)

| Code | Meaning | Notes |
| --- | --- | --- |
| `3` | Execution reverted | `error.data` carries the raw revert payload (`'0x...'`). |
| `-32700` | Parse error | Malformed JSON passed to `rpc()` or HTTP/WS server. |
| `-32600` | Invalid request | Missing required JSON-RPC 2.0 envelope fields or empty batch `[]`. |
| `-32601` | Method not found | Unregistered JSON-RPC method name. |
| `-32602` | Invalid params | Wrong parameter types, counts, or invalid fork URL. |
| `-32603` | Internal error | Engine unavailable (`503` on HTTP) or unexpected runtime failure. |
| `-32000` | Execution / admission error | E.g. gas limit exceeding the Osaka cap (`16,777,216`), insufficient funds, or nonce mismatch. |

`createMemoryClient` attaches viem's full public, wallet, and Anvil test action sets. A viem helper existing on the client does not guarantee every obscure parameter extension is implemented in ZEVM. For exact native RPC details, consult the [ZEVM JSON-RPC docs](https://zevm.sh/docs/reference/json-rpc/overview/).
</WatchOut>
