# Call, contract & deploy

Three action functions cover nearly all EVM execution: `tevmCall` (raw calldata), `tevmContract` (ABI-encoded calls with typed return decoding), and `tevmDeploy` (contract creation).

All three are attached to `createMemoryClient()` and also exported as standalone tree-shakeable functions from `tevm` and `tevm/actions`.

<ExecutionFlowDiagram />

## `tevmCall`

Executes an `eth_call` simulation by default. Pass `addToMempool: true` to queue a transaction via `eth_sendTransaction`, or `addToBlockchain: true` to submit and ensure a block is mined.

### Parameters (`CallParams`)

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `to` | `Address` | — | Recipient or contract address (omit for deployment). |
| `from` | `Address` | first `eth_accounts` entry (for txs) | Caller / sender address. |
| `data` | `Hex` | `'0x'` | Calldata or creation bytecode. |
| `value` | `bigint` | — | Value in wei. |
| `gas` | `bigint` | — | Gas limit. |
| `gasPrice` | `bigint` | — | Legacy gas price in wei. |
| `maxFeePerGas` | `bigint` | — | EIP-1559 max fee per gas. |
| `maxPriorityFeePerGas` | `bigint` | — | EIP-1559 priority fee. |
| `nonce` | `bigint` | — | Explicit sender nonce. |
| `blockTag` | `string` | `'latest'` | Block tag or hex number for `eth_call`. |
| `stateOverride` | `Record<string, JsonValue>` | — | Standard `eth_call` state overrides (`balance`, `nonce`, `code`, `state`, `stateDiff`). |
| `addToMempool` | `boolean` | `false` | Submits via `eth_sendTransaction` and returns `{ rawData: '0x', txHash }`. |
| `addToBlockchain` | `boolean` | `false` | Submits and mines a block if no receipt exists yet; returns `{ rawData: '0x', txHash, receipt }`. |

### Return type (`CallResult`)

```ts
type CallResult = {
  rawData: Hex
  txHash?: Hex
  receipt?: JsonValue
}
```

### Simulation with `stateOverride`

`stateOverride` lets you replace bytecode, balances, or storage slots for a single `eth_call` without mutating chain state:

```ts
import { createMemoryClient, toHex } from 'tevm'

const client = createMemoryClient()
try {
  const target = '0x0000000000000000000000000000000000000123'

  const result = await client.tevmCall({
    to: target,
    stateOverride: {
      [target]: { code: '0x602b60005260206000f3' },
    },
  })

  console.log(result.rawData) // 0x000...002b (43)
  console.log(await client.getCode({ address: target })) // undefined (chain unchanged)
} finally {
  await client.tevmClose()
}
```

## `tevmContract`

ABI-encodes `functionName` and `args`, delegates to `tevmCall`, and ABI-decodes `rawData` into `data` for read-only calls. Accepts either `address` or `to`.

```ts
import { createMemoryClient, parseAbi } from 'tevm'

const client = createMemoryClient()
try {
  const address = '0x0000000000000000000000000000000000000123'
  await client.tevmSetAccount({
    address,
    deployedBytecode: '0x602a60005260206000f3',
  })

  const abi = parseAbi(['function answer() view returns (uint256)'])

  // Read simulation: decodes `data` with full TypeScript return inference
  const readResult = await client.tevmContract({
    address,
    abi,
    functionName: 'answer',
  })
  console.log(readResult.data) // 42n (typed as bigint | undefined)

  // State-changing call: submits & mines; `data` is undefined, `txHash` & `receipt` are populated
  const writeResult = await client.tevmContract({
    address,
    abi,
    functionName: 'answer',
    addToBlockchain: true,
  })
  console.log(writeResult.txHash)
} finally {
  await client.tevmClose()
}
```

## `tevmDeploy`

Encodes `bytecode` plus optional constructor `abi` and `args`, submits the creation transaction, and mines it immediately unless `addToMempool: true` is passed.

```ts
import { createMemoryClient } from 'tevm'

const client = createMemoryClient({ mining: { auto: false } })
try {
  // Mined immediately by default -> createdAddress is populated
  const deployed = await client.tevmDeploy({
    bytecode: '0x600a600c600039600a6000f3602a60005260206000f3',
  })
  console.log('Deployed at:', deployed.createdAddress)

  // Queued to mempool -> createdAddress is undefined until you mine
  const pending = await client.tevmDeploy({
    bytecode: '0x600a600c600039600a6000f3602a60005260206000f3',
    addToMempool: true,
  })
  console.log('Pending tx:', pending.txHash, 'address:', pending.createdAddress)
  await client.tevmMine({ blocks: 1 })
} finally {
  await client.tevmClose()
}
```

## Handling reverts and native errors

When EVM execution reverts, `tevmCall` and `tevmContract` reject with `NativeRpcError` where `code === 3` and `data` contains the raw revert payload:

```ts
import { createMemoryClient, NativeRpcError } from 'tevm'

const client = createMemoryClient()
try {
  const target = '0x0000000000000000000000000000000000000123'
  // PUSH4 0xdeadbeef; PUSH1 0; MSTORE; PUSH1 4; PUSH1 28; REVERT
  await client.tevmSetAccount({
    address: target,
    deployedBytecode: '0x63deadbeef6000526004601cfd',
  })

  await client.tevmCall({ to: target })
} catch (error) {
  if (error instanceof NativeRpcError) {
    console.log({ code: error.code, data: error.data })
    // { code: 3, data: '0xdeadbeef' }
  }
} finally {
  await client.tevmClose()
}
```

<QaBox question="Can I use tevmCall and tevmContract against a remote HTTP server or in a browser?">
Yes. Standalone `tevmCall`, `tevmContract`, `tevmDeploy`, and the other helpers in `@tevm/actions` accept any `RpcClient` (`{ request(req): Promise<JsonValue> }`) and have no native Node.js imports. Pass a viem HTTP client, a `ZevmEngine`, or a `MemoryClient`.
</QaBox>

<WatchOut title="Transaction results do not decode return data">
When `addToMempool: true` or `addToBlockchain: true` is set, `tevmContract` submits an Ethereum transaction and returns `{ rawData: '0x', txHash, receipt? }` with `data: undefined`. Simulate first (default) if you need the ABI-decoded return value.
</WatchOut>
