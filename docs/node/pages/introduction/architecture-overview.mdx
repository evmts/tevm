# Architecture

Tevm is structured as a thin, typed JavaScript host layer over a native Zig Ethereum node. Every host API — `MemoryClient`, `TevmProvider`, `@tevm/server`, `@tevm/mcp`, and standalone actions — routes through one serialized boundary: `ZevmEngine`.

<ArchitectureDiagram />

## Layer ownership

| Layer | Package / Repo | Owns |
| --- | --- | --- |
| **EVM interpreter** | Guillotine Mini (Zig) | Opcode execution, hardfork rules, gas accounting, `debug_traceCall` tracer |
| **Primitives & state** | Voltaire (Zig) | Accounts, bytecode, storage slots, crypto, RLP, precompiles |
| **Node runtime** | ZEVM (Zig) | `NodeRuntime`, chain, mempool, mining, receipts, filters, snapshots, fork backend, JSON-RPC dispatcher |
| **Native bridge** | `@tevm/node` | Node-API handle, serialized request queue, `NativeRpcError`, `events`, `ready()`, `close()` |
| **Viem client** | `@tevm/memory-client` | `createMemoryClient`, `createTevmTransport`, `tevmViemActions` (`cacheTime: 0`) |
| **Actions** | `@tevm/actions` | Browser-safe typed RPC helpers (`tevmCall`, `tevmContract`, `tevmDeploy`, `tevmSetAccount`, etc.) |
| **Servers** | `@tevm/server` | HTTP POST/batch, WebSocket subscriptions, Unix IPC framing, Express & Next.js adapters |

Each `ZevmEngine` owns one native `NodeRuntime` handle. Two engines never share state.

## The `ZevmEngine` boundary

`createZevmEngine(options)` (also exported as `createTevmNode`) instantiates `NativeNode` from `@evmts/zevm` and wraps it with five members:

| Member | Contract |
| --- | --- |
| `ready()` | Resolves once initial fork and mining configuration completes. Rejects and frees the native handle if initialization fails. |
| `request({ method, params })` | Enqueues one JSON-RPC call, returns the parsed `result`, or throws `NativeRpcError` (`code`, `message`, optional `data`). |
| `rpc(jsonString)` | Enqueues raw JSON-RPC wire text (single requests, batches, or notifications) and returns the exact response JSON string, or `null` for notifications. |
| `events` | Node `EventEmitter` emitting `request`, `response`, `block`, and `close`. |
| `close()` | Stops the block-poll timer, releases the native handle, emits `close`, and removes listeners. Idempotent. |

### Request serialization

JavaScript callers may invoke `request()` and `rpc()` concurrently with `Promise.all`. Inside `ZevmEngine`, an internal promise queue executes every call against the native handle strictly one at a time in FIFO order. This guarantees deterministic state transitions without requiring manual locks in user code.

### Block observation

When at least one listener is attached to `engine.events.on('block', ...)`, `ZevmEngine` checks `eth_blockNumber` after each dispatched RPC and on a lightweight unreferenced 50 ms timer (so blocks mined on ZEVM's background interval-mining Zig thread are observed without polling from user code). Removing all `block` listeners stops the timer immediately.

## `MemoryClient` and the transport boundary

`createMemoryClient(options)` builds a viem client configured with `cacheTime: 0` and `createTevmTransport(options)`, then extends it with:

1. viem `publicActions` (`getBlock`, `getBalance`, `getLogs`, `getTransactionReceipt`, `readContract`, …)
2. viem `walletActions` (`sendTransaction`, `writeContract`, `deployContract`, …)
3. viem `testActions({ mode: 'anvil' })` (`setBalance`, `setCode`, `mine`, `snapshot`, `revert`, `increaseTime`, …)
4. `tevmViemActions()` (`tevmReady`, `tevmClose`, `tevmCall`, `tevmContract`, `tevmDeploy`, `tevmSetAccount`, `tevmGetAccount`, `tevmDeal`, `tevmMine`, `tevmDumpState`, `tevmLoadState`)

Every action translates to one or more JSON-RPC calls dispatched through `client.transport.tevm`. Because every surface shares that single engine, a balance set with `client.setBalance()` is immediately visible to `client.tevmGetAccount()`, `client.request({ method: 'eth_getBalance', ... })`, and any attached `@tevm/server`.

## Execution paths

<ExecutionFlowDiagram />

1. **Read / simulate (`eth_call`, `tevmCall`)** — executes against current state (plus optional `stateOverride`), discards state changes, and returns raw bytes (`rawData`). Reverts throw `NativeRpcError` with `code: 3` and revert `data`.
2. **Queue (`addToMempool: true` with `mining: { auto: false }`)** — submits via `eth_sendTransaction`, leaves the transaction pending in ZEVM's txpool, and returns `{ rawData: '0x', txHash }`. `getTransactionReceipt` returns `null` until mined.
3. **Mine (`addToBlockchain: true`, automine, or `tevmMine()`)** — executes pending transactions in Guillotine Mini, commits the state transition in Voltaire, appends a canonical block, and indexes receipts and logs.

## Resource lifecycle

Native handles live outside V8's garbage collector. Always close what you open:

- `MemoryClient`: `await client.tevmClose()` (also closes an externally supplied `engine`).
- `ZevmEngine`: `await engine.close()`.
- `TevmProvider` (`@tevm/ethers`): `provider.destroy()`.
- `createServer` / `createIpcServer`: close the server, then call `await client.tevmClose()`.

Calling `request()` or `rpc()` on a closed engine rejects with `Error('engine is closed')`.
