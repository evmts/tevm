# What is Tevm?

Tevm embeds a native Ethereum execution node directly inside Node.js and exposes it through viem-compatible clients, an event emitter, and HTTP, WebSocket, and IPC JSON-RPC servers.

Underneath the TypeScript surface sits a native Zig stack loaded via Node-API:

- **Guillotine Mini** executes EVM bytecode, enforces hardfork rules, and records opcode traces.
- **Voltaire** owns Ethereum primitives, cryptography, RLP, and account/storage state.
- **ZEVM** implements the node runtime: chain state, mempool, mining, receipts, filters, snapshots, fork backend, and JSON-RPC dispatcher.

## What Tevm provides

- **Isolated in-process chains** — `createMemoryClient()` allocates an independent local chain in milliseconds with no external daemon or port collisions.
- **Viem-native client** — public, wallet, Anvil-compatible test actions, and `tevm*` helpers share one client with `cacheTime: 0`.
- **Lazy state forking** — fork any upstream EVM JSON-RPC endpoint at a pinned block; writes remain local.
- **Multi-transport JSON-RPC server** — serve any client over HTTP, WebSocket subscriptions, Unix IPC, Express, or Next.js via `tevm/server`. Browser apps connect to this server with standard viem transports.
- **Direct Solidity imports** — compile `.sol` files into typed ES modules at build time with `tevm/bundler/*` and `@tevm/ts-plugin`.
- **Native opcode tracing and MCP** — capture structured Guillotine Mini traces via `debug_traceCall`, or expose isolated EVM sessions to AI coding agents with `@tevm/mcp`.

## How Tevm compares

| Capability | Tevm | Anvil | Hardhat Network |
| --- | --- | --- | --- |
| **Execution engine** | Native Zig (ZEVM / Voltaire / Guillotine Mini) | Native Rust (revm) | Rust (EDR) / JS |
| **In-process Node.js API** | Yes (Node-API, isolated per client) | External process over HTTP | In-process via Hardhat runtime |
| **Viem integration** | Native (`createMemoryClient`) | External RPC transport | External RPC transport |
| **Ethers v6 integration** | Native (`TevmProvider` / `BrowserProvider`) | External RPC transport | Hardhat plugin |
| **HTTP / WS / IPC server** | Built-in (`tevm/server`) | HTTP / WS | HTTP |
| **Mainnet state forking** | Lazy read-through overlay | Lazy read-through overlay | Lazy read-through overlay |
| **Direct `.sol` imports in TS** | Built-in (`tevm/bundler/*`) | No | No |
| **AI agent MCP server** | Built-in (`@tevm/mcp`) | No | No |

## Library compatibility

| Library | Integration |
| --- | --- |
| [**viem**](../getting-started/viem) | First-class client via `createMemoryClient()` or tree-shakeable `createTevmTransport()` |
| [**ethers.js v6**](../getting-started/ethers) | Direct `TevmProvider` (`@tevm/ethers`) or `BrowserProvider(client, undefined, { cacheTimeout: -1 })` |
| **Browser apps (viem / wagmi)** | Connect over HTTP or WebSocket to `createServer(client)` from `tevm/server` |
| **Any EIP-1193 or JSON-RPC client** | `client.request({ method, params })`, `engine.rpc(json)`, or `tevm/server` |
