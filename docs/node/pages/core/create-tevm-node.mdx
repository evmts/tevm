# Client & engine options

`createMemoryClient`, `createTevmTransport`, and `createZevmEngine` (`createTevmNode`) all share the same core engine options (`ZevmEngineOptions`). `createMemoryClient` adds viem client fields on top.

## Basic initialization

```ts
import { createMemoryClient } from 'tevm'

const client = createMemoryClient()
try {
  // Optional: wait eagerly for fork/mining initialization
  await client.tevmReady()
  console.log(await client.getChainId(), await client.getBlockNumber())
  // 31337 0n
} finally {
  await client.tevmClose()
}
```

Construction is synchronous. The engine runs its startup configuration (fork reset, automine, interval mining) on an internal promise queue; `await client.tevmReady()` resolves when that setup completes and rejects immediately if setup fails (for example, an unreachable fork URL).

## Complete option reference

### `ZevmEngineOptions`

Accepted by `createZevmEngine`, `createTevmNode`, `createTevmTransport`, and `createMemoryClient`:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `chainId` | `number` | `31337` | Unsigned safe integer chain ID passed to ZEVM (`chain_id`). |
| `mining` | `{ auto?: boolean; interval?: number }` | `{ auto: true }` | Automine flag and optional background interval in whole seconds (`0` disables the timer). |
| `fork` | `{ url: string; blockNumber?: number }` | `undefined` | Upstream JSON-RPC URL and optional pinned block number (unsigned safe integer). |

### `MemoryClientOptions` (extends `ZevmEngineOptions`)

Accepted by `createMemoryClient`:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `engine` | `ZevmEngine` | new engine | Supply an existing `ZevmEngine` instead of creating one. `tevmClose()` still closes it. |
| `common` | `Chain` (viem) | `foundry` (with `chainId`) | Viem `Chain` metadata attached to the client (name, currency, contracts). Does not alter ZEVM's hardfork schedule. |
| `account` | `Account \| Hex` | `undefined` | Default account for viem wallet actions (`sendTransaction`, `writeContract`, `deployContract`). |
| `name` | `string` | `'TEVM'` | Viem client display name. |
| `key` | `string` | `'tevm'` | Viem client key. |

<WatchOut title="Validation rules">
`chainId`, `mining.interval`, and `fork.blockNumber` must be unsigned safe integers (`Number.isSafeInteger(v) && v >= 0`). Negative numbers, floats, or values above `Number.MAX_SAFE_INTEGER` throw a synchronous `TypeError`.
</WatchOut>

## Configuring chain identity

Pass `chainId` to configure the native engine's chain ID, and optionally `common` for viem chain metadata:

```ts
import { createMemoryClient } from 'tevm'
import { optimism } from 'tevm/common'

const client = createMemoryClient({
  chainId: optimism.id,
  common: optimism,
})

try {
  console.log(await client.getChainId()) // 10
} finally {
  await client.tevmClose()
}
```

Passing `common` alone sets the viem `Chain` object on the client; set `chainId` explicitly when the native engine's `eth_chainId` must match a specific network (such as mainnet `1` or Optimism `10`).

## Sharing an engine with a custom viem client

Create the engine once and pass it into `createMemoryClient({ engine })` or `createTevmTransport({ engine })`:

```ts
import { createMemoryClient, createZevmEngine } from 'tevm'

const engine = createZevmEngine({
  chainId: 31337,
  mining: { auto: false },
})

const client = createMemoryClient({ engine })

try {
  await client.tevmReady()
  console.log(await client.getBlockNumber()) // 0n
} finally {
  // Also closes the supplied engine
  await client.tevmClose()
}
```

## Closing and cleanup

Every engine holds native memory and, in interval mode, a background Zig thread. Always call `await client.tevmClose()` (or `await engine.close()`) when finished.

If initialization fails (for example, an invalid `fork.url`), `createZevmEngine` closes the native handle automatically and rejects both `ready()` and any subsequent `request()` with the startup `NativeRpcError`.
