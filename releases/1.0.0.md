# tevm 1.0.0

tevm 1.0.0 is the first stable release of the in-process Ethereum execution
environment. It combines a synchronous memory client with viem public, wallet,
and test actions, explicit block production, transaction pooling, receipts,
tracing, state controls, and network forking.

This release is based on `1.0.0-rc.151`. The comparison baseline for the
release-candidate work is `1.0.0-next.149`.

## What users will notice

- The memory client works as a viem-compatible client. Standard public, wallet,
  and test actions share the same in-memory chain as Tevm actions.
- The JSON-RPC surface is substantially broader. The release-candidate line
  completed and hardened methods for blocks, transactions, receipts, logs,
  proofs, fee history, simulation, snapshots, time controls, mining, filters,
  and the `anvil_*`, `debug_*`, `eth_*`, `evm_*`, and `txpool_*` namespaces.
- Mining supports manual, automatic, and working interval modes. Interval
  configuration uses `blockTime` in seconds.
- Transaction lifecycle behavior is consistent across Tevm actions, JSON-RPC,
  and viem. Transactions enter the pool, mining creates canonical blocks, and
  receipts and transaction lookups follow the canonical chain.
- Tracing includes structured logs plus `flatCallTracer` and `muxTracer`
  support for debug call and transaction workflows.
- EIP-7702 delegated EOA code transactions are supported and gated by the
  active hardfork.
- Forked clients can infer a chain configuration when `common` is omitted,
  while an explicit `common` remains the fastest and most predictable setup.

## Correctness and compatibility

The release-candidate work added conformance and parity coverage, then fixed
issues found across the EVM, VM, state, blockchain, actions, receipts, txpool,
precompiles, server, bundlers, and client integrations.

The stable release also includes the post-rc.151 correctness pass from
`4196792e1`. Among its fixes are checkpoint-safe storage clearing, canonical
same-height reorg indexing, listener error propagation, corrected trace gas and
depth values, gas-weighted fee-history rewards, historical balance cache keys,
storage-range pagination, interval-mining error propagation, txpool retention,
and ABI-encoded precompile revert reasons.

Receipt and log handling now covers legacy receipts, null log topics,
32-byte-padded storage values, canonical block receipts, and fork fallbacks
without the failures seen in the prerelease line.

## Important migration notes

- `createMemoryClient()` is synchronous. Use `await client.tevmReady()` only
  when eager initialization is required before the first action.
- `client.request` is the EIP-1193 surface and accepts `{ method, params }`.
  The lower-level JSON-RPC envelope remains available through
  `client.transport.tevm.request`.
- The optional second retry-options argument previously accepted by
  `client.request` is no longer part of the EIP-1193 surface.
- Interval mining changed from
  `{ type: "interval", interval: milliseconds }` to
  `{ type: "interval", blockTime: seconds }`.
- Gas-threshold mining was removed. Use manual, automatic, or interval mining.
- `StateManager.initBinaryTreeExecutionWitness` was removed. Verkle and
  EIP-6800 execution is rejected explicitly instead of attempting partial
  witness execution.
- Use chain presets from `tevm/common`, not the transient `tevm/chains`
  subpath.
- viem `^2.49.3` is the supported peer range at the release-candidate
  baseline.

See [the 1.0.0 migration guide](./1.0.0-migration.md) for tested before and
after examples and package-entry-point guidance.

## Historical clarification

Blocks, the initial receipt manager and txpool, the synchronous client,
EIP-1193 compatibility, and the first trace configuration did not first appear
between `next.149` and `rc.151`. The repository release notes show those
foundations landing by `next.41` and `next.42`.

The `next.149` to `rc.151` range made those systems release-ready. It expanded
RPC coverage, implemented interval mining, added additional tracers and
simulation methods, integrated EIP-7702, upgraded the underlying execution
facade, added conformance tooling, and fixed cross-package correctness and
compatibility defects.
