# Forking

A fork reads accounts, contract code, and storage slots lazily from an upstream JSON-RPC endpoint and stores every write in a local overlay. It never copies the whole chain and never writes upstream.

## Configure a fork

Pass `fork: { url, blockNumber }` alongside the matching `chainId` and `common` preset:

```ts
import { createMemoryClient } from 'tevm'
import { mainnet } from 'tevm/common'

const client = createMemoryClient({
  chainId: mainnet.id,
  common: mainnet,
  fork: {
    url: process.env.MAINNET_RPC_URL ?? 'https://ethereum-rpc.publicnode.com',
    blockNumber: 20_000_000,
  },
})

try {
  await client.tevmReady()

  const vitalik = '0xd8dA6BF26964aF9D7eEd9e03E53415D37aA96045'
  const balance = await client.getBalance({ address: vitalik })

  // Local write stays in memory; upstream mainnet is untouched
  await client.tevmDeal({ address: vitalik, amount: balance + 1n })
} finally {
  await client.tevmClose()
}
```

<QaBox question="Why does getBlockNumber() return 0n right after forking?">
ZEVM forks upstream **state** at your pinned `blockNumber` into a fresh local chain starting at block height `0`. Historical upstream block headers are not imported; local blocks mined on the fork start at `1`, `2`, `3`, and so on.
</QaBox>

<WatchOut title="Do not fork a server on the same Node.js event loop">
ZEVM performs fork HTTP requests synchronously in native Zig code. If a test runs a local mock upstream server, launch that server in a separate OS process (`node:child_process`) so the native request cannot block the JavaScript thread serving it.
</WatchOut>

## Operational rules

| Choice | Result |
| --- | --- |
| Pin `blockNumber` | Reproducible upstream state across every run |
| Omit `blockNumber` | Forks from the upstream head at startup |
| Set `chainId` + `common` | Matches upstream chain ID and viem metadata |
| First read of an address/slot | Fetches once from upstream and caches locally |
| Any write or mined block | Stored in the local overlay only |
| Switch fork block | Call `anvil_reset` with new `forking` params, or create a new client |
