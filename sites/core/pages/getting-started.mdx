# Getting started

Requires **Node.js 24 or later**. Install `tevm` alongside `viem`:

```bash
pnpm add tevm viem
```

## Create a client

`createMemoryClient()` allocates an isolated native ZEVM chain synchronously (default chain ID `31337`, block `0`, automining enabled). Call `tevmReady()` when you want startup configuration — especially a fork — to finish eagerly.

```ts
import assert from 'node:assert/strict'
import { createMemoryClient } from 'tevm'

const client = createMemoryClient()
try {
  await client.tevmReady()
  assert.equal(await client.getBlockNumber(), 0n)
  assert.equal(await client.getChainId(), 31337)
} finally {
  await client.tevmClose()
}
```

<WatchOut title="Always call tevmClose()">
Each client holds a native ZEVM handle outside V8's garbage collector. Wrap usage in `try { ... } finally { await client.tevmClose() }` so native memory and interval timers shut down cleanly.
</WatchOut>

One client exposes five surfaces over the exact same native chain:

| Surface | Use it for | Representative methods |
| --- | --- | --- |
| Public actions | Read chain state | `getBalance`, `getBlock`, `getLogs`, `readContract` |
| Wallet actions | Submit transactions | `sendTransaction`, `writeContract`, `deployContract` |
| Test actions | Prepare scenarios | `setBalance`, `setCode`, `mine`, `snapshot`, `revert` |
| TEVM actions | Direct engine helpers | `tevmCall`, `tevmContract`, `tevmDeploy`, `tevmDumpState` |
| EIP-1193 | Raw JSON-RPC | `request({ method, params })` |

## Deploy and call a contract

<CoreCallFlowDiagram />

Deploy creation bytecode with `tevmDeploy`, then decode typed return values with `tevmContract`:

```ts
import assert from 'node:assert/strict'
import { createMemoryClient, parseAbi } from 'tevm'

const client = createMemoryClient()
try {
  const deployed = await client.tevmDeploy({
    bytecode: '0x600a600c600039600a6000f3602a60005260206000f3',
  })
  assert.ok(deployed.createdAddress)

  const result = await client.tevmContract({
    address: deployed.createdAddress,
    abi: parseAbi(['function answer() view returns (uint256)']),
    functionName: 'answer',
  })

  assert.equal(result.data, 42n)
} finally {
  await client.tevmClose()
}
```

<QaBox question="When should I use setCode / tevmSetAccount instead of tevmDeploy?">
When a test does not need constructor logic, installing runtime bytecode directly with `tevmSetAccount({ address, deployedBytecode })` or `setCode({ address, bytecode })` places code at a deterministic address with zero transaction overhead.
</QaBox>
